# UATシナリオ自動作成Skill

変更資料・関連仕様から、根拠付きのUAT（ユーザー受入テスト）シナリオを自動作成するAI Skillです。確認条件、前提、テストデータ、操作手順、期待結果、観測方法、未確定事項を整理し、JSONとMarkdownで出力します。

Skill名：`uat-scenario-design` / 出力契約：v0.7 / 補助スクリプト：TypeScript

AIがSkillの指示に沿って資料を読み、シナリオを作成します。付属スクリプトは生成済みJSONの検査と表示を担当します。スクリプト単独ではシナリオを生成しません。

## 最初の準備

1. このプロジェクトを、資料を読み書きできるAIの作業場所に配置します。
2. Node.js 22.18以上の22系、または24以降を用意します。
3. プロジェクト直下で次を実行します。

~~~powershell
npm ci
npm run typecheck
npm test
~~~

案件資料はリポジトリ外の非公開フォルダ、またはGit管理対象外の`private/`に置きます。フォルダ名・マッピング・生成結果・チーム固有ルールも業務情報として扱います。`.gitignore`はZIP作成時や登録済みファイルには適用されないため、公開・転送前に[共有手順](docs/sharing.md)を確認してください。

## 1. 実案件に合わせてSkillを更新する

過去案件の**完成シナリオと、作成時に渡されたインプット資料の組**を用意します。完成シナリオだけでも書式や粒度は確認できますが、要件の拾い方、期待結果の根拠、漏れの評価には入力資料が必要です。

1. [案件マッピングのひな形](templates/case-map.md)を非公開側へコピーし、各案件の入力、完成シナリオ、資料版、対象チーム・機能エリアを対応付けます。既存のマッピングも同じ情報があれば使えます。
2. 完成シナリオの内容を分析する前に、調整に使う案件と、最終評価に残す案件を案件単位で分けます。同じ仕様・資料を共有する案件は同じ組にまとめます。
3. 現行Skillを固定して生成・評価します。再現した問題を基に、共通の作成手順とチーム・機能エリア固有のルールを分け、必要な箇所だけ更新します。
4. 調整用案件で確認後、未使用の評価用案件で生成・独立レビューを行います。採用条件を満たした範囲と、残る制限を非公開側に記録します。

AIへの依頼例（パスを実際の保存先に置き換えてください）：

> README.mdとdocs/adapting.mdを読み、private/case-map.mdに対応する資料でSkillを評価・更新してください。最初に案件の適用範囲と評価用の分離を確認してください。評価用の完成シナリオは生成側に渡さず、現行Skillの基準結果を残してください。修正は検証で必要性を確認した場合だけ行い、不要なら変更しないでください。案件資料・評価結果・固有ルールはprivate/内に保存してください。

詳細は[実案件を用いた更新手順](docs/adapting.md)を参照してください。資料を渡すだけでモデル自体が学習されるわけではありません。更新対象はSkillの指示、参照ルール、必要に応じた検査コードです。

## 2. 更新・採用後にシナリオを作成する

1. 今回の変更資料、有効な関連仕様、対象チーム・機能エリアを指定します。
2. 確認済みの適用ルールと、参照可能な過去シナリオ・観点表・出力テンプレートがあれば渡します。別エリアのルールをそのまま適用しません。
3. 次のようにAIへ依頼します。

> skills/uat-scenario-design/SKILL.mdを読み、private/current-case/の資料からUATシナリオを作成してください。適用範囲は［対象チーム・機能エリア］、確認済みルールはprivate/rule-profile.mdです。資料の版と根拠を確認し、未確定事項は保留と質問にしてください。成果物はprivate/runs/内の新しいフォルダへ保存し、構造検査・原文照合・Markdown生成まで行ってください。

ルールファイルがない場合は、その指定を依頼から外してください。プロファイルを自動選択する仕組みはありません。使う資料・ルールを依頼時に指定します。

4. 出力をレビューし、重要な漏れ、期待結果、操作・観測の実行可能性、確認事項を確認してから業務で使用します。

資料を最初からJSONに変換する必要はありません。AIが原資料から参照索引を作ります。読み取れない形式や不足資料がある場合は、その範囲を明示します。基本の対象は1案件＝1機能の変更程度です。

## 出力と検査

|ファイル|内容|
|---|---|
|`source-index.json`|原資料の参照索引|
|`draft-*.json` / `check-*.json`|草稿と検査記録|
|`output.json`|シナリオ、根拠、要件対応、確認事項|
|`output.md`|レビュー用の表示|

`ready`は資料上シナリオを実行できる状態、`pending`は未確定事項が残る状態です。生成・構造検査の合格は、業務上の正しさ、承認、テスト実行の完了を意味しません。

~~~powershell
$uatRun = 'private/runs/example'
node scripts/check_output.ts --fixture "$uatRun/source-index.json" --output "$uatRun/output.json"
node scripts/render_output.ts --input "$uatRun/output.json" --output "$uatRun/output.md"
~~~

表示の保存先には、まだ存在しないファイル名を指定します。
