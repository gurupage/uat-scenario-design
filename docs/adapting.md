# 実案件を用いた更新手順

過去の完成シナリオと、その作成に使った入力資料を対応付け、再生成と比較によって必要な改善を確認します。評価対象のチーム・機能エリアと適用条件を定め、その範囲での適合性を確認します。

## 1. 資料と対象範囲を確定する

[案件マッピング](../templates/case-map.md)に、案件ID、チーム・機能エリア、入力資料、完成シナリオ、版、共有仕様、欠落資料を記録します。同じチーム・同じエリアでも運用変更や例外案件があり得るため、有効期間と例外を確認します。入力資料は可能な限り当時の版を使い、後から確定した情報と区別します。

実案件の名称・資料・マッピング・生成結果・評価記録・抽出ルールは非公開側に保存します。公開側には汎用化できた変更と、実案件の情報を含まない架空テストのみを反映します。

## 2. 調整用と最終評価用に分ける

内容分析を始める前に、案件単位で用途を固定します。調整に使う案件と、最終評価まで参照しない案件を分けます。件数だけで決めず、類似案件や共有資料が両側に入りすぎないこと、対象の主要な変更種類を評価できることを確認します。少数案件での合格は、全案件での品質保証にはなりません。

最終評価用の完成シナリオと評価基準は評価担当だけが参照します。生成担当には、その案件の当時の入力と、調整用案件から得た確認済みルールのみを渡します。最終評価の結果を見て修正した場合、その案件は調整済みです。修正後の未使用評価には別案件を用意し、同じ案件の再試行を未使用評価と呼びません。

## 3. 現行Skillの結果を基準にする

Skill・検査コードの版またはファイルのハッシュ、使用AI、生成条件、入力版を記録します。調整用案件を現行Skillで生成し、草稿・検査失敗・最終結果を新しい保存先に残します。新しい会話での反復試行も行い、同じ問題が繰り返されるかを確認します。改善前後で資料や生成条件を不用意に変えないようにします。

## 4. 比較して原因を分ける

完成シナリオは比較資料として使い、無条件の正解とはしません。原資料から必要性を確認し、過去シナリオ側の漏れ・古い仕様・暗黙の運用も区別します。

|評価項目|判断の根拠|
|---|---|
|重要条件の漏れ|変更・影響・役割・状態ごとに必要な条件が対応しているか|
|期待結果の正確さ|有効な仕様の該当箇所に戻れるか。創作や旧動作の混入がないか|
|実行可能性|前提、データ準備、権限、操作経路、観測方法を説明できるか|
|保留の妥当性|不足部分は保留し、独立して確定できる部分は作れているか|
|粒度と負担|業務上必要な深さがあり、不要な重複や過剰な質問がないか|
|修正負担|レビュー・修正・確認対応を含む時間と修正箇所|

同じ言い回しや件数への一致率だけで判定しません。資料不足、Skillの指示不足、案件固有条件、生成のばらつきを分けます。

## 5. 必要な変更だけを行う

|変更の種類|置く場所|
|---|---|
|案件を問わない作成・根拠確認・保留の手順|Skill本体・汎用参照文書|
|特定チーム・機能エリアの範囲、用語、粒度、運用|非公開の[適用ルール](../templates/rule-profile.md)|
|その案件の仕様、値、操作、例外|案件資料・参照索引|
|構造検査で再現する不具合|検査コードと架空の回帰テスト|

同じチームの複数例で共通していても、別チーム共通とは断定しません。適用条件を明示し、異なる範囲のルールを混同しないか検証します。両立しない手順や出力契約があり、適用範囲を指定しても混同が繰り返される場合に、Skillの分割を検討します。

各変更について、観測した問題、根拠、対象範囲、変更理由、再確認方法を非公開の評価記録に残します。必要性が確認できなければ変更しません。

## 6. 再評価して採用する

コード・出力形式を変えた場合は型検査と回帰検査を行います。指示だけを変えた場合も、影響する案件で再生成して内容を比較します。その後、固定した候補版を未使用の評価用案件で確認します。生成とは別の担当者または独立したAIの文脈で原資料と照合し、業務上の採用判断はレビュー担当者が行います。

評価前に採用条件を決めます。例として、重大な期待結果の誤り・重要条件の漏れ・根拠のない操作や観測方法が残っていないこと、未確定事項が保留になっていること、レビュー修正負担が許容範囲にあることを確認します。判定不能は合格扱いにしません。

採用版、適用できる範囲、確認した案件、残る制限を非公開側に記録し、通常利用ではその版と適用ルールを指定します。評価が足りない場合は試用扱いにし、次の評価案件を明示します。適用範囲を変更する場合は、変更先の入力と完成シナリオで適合性を評価します。
