# 検証手順

生成結果の構造、原資料に対する内容、実案件での適合性を分けて確認する。スクリプトはTypeScriptを使う。

## 実行環境と基本確認

Node.js 22.18以上の22系、または24以降を使用する。以下はプロジェクト直下で実行する。

```powershell
npm ci
npm run typecheck
npm test
node scripts/validate_skill.ts skills/uat-scenario-design
```

検査・表示・テストはNode.jsの標準機能で実行する。型検査の開発依存はpackage-lockに固定している。Nodeの直接TS実行自体は型検査をしないため、コード変更時は型検査も行う。

## 生成結果の検査と表示

次の「<実行名>」を対象の実行フォルダに置き換える。

~~~powershell
$uatRun = 'private/runs/<実行名>'
node scripts/check_output.ts --fixture "$uatRun/source-index.json" --output "$uatRun/output.json"
node scripts/render_output.ts --input "$uatRun/output.json" --output "$uatRun/readable.md"
~~~

検査は現行Skillの出力契約と照合する。表示の保存先には存在しないファイル名を指定する。構造検査は参照関係・必須項目・状態の整合性を確認し、内容の正しさは原資料と照合する。

Skill形式検査は、このSkillに必要なfrontmatter・命名・ローカル参照を確認する。

## 新規生成の評価

1. 検証したい不確かさと対象範囲を決める。
2. 原資料と評価基準を生成前に固定する。必須条件、禁止する断定、必要な保留、独立して確定できる部分を明記する。
3. 基準が原資料から判定可能かを確認する。特に観測経路の存在と、各時点で観測を必須にする根拠を分けて確かめる。
4. Skillを固定し、原資料とSkillだけを渡して新しい文脈で生成する。過去回答や評価基準を生成側へ渡さない。
5. 初稿、検査失敗、自主修正、最終出力を保存する。検査済み草稿と最終JSON、Markdownの内容が一致するかを照合する。
6. 生成とは独立したレビューで、原文→参照索引→シナリオの内容を評価する。
7. 発見事項、修正の必要性、変更した場合の回帰確認、残る未評価事項を記録する。

同一文脈での修正や保存済み出力の再検査を新しい独立生成に数えない。資料・基準の曖昧さは生成側の不備と分け、判定不能を合格に補完しない。凍結した評価基準や失敗原本を事後に書き換えない。

## 内容レビュー

|項目|確認する内容|
|---|---|
|範囲|観点表と過去例を参照し、案件固有条件を整理しているか|
|根拠|資料にない機能・値・メッセージ・動作を確定していないか|
|網羅性|役割、状態、境界、例外、関連動作の重要な欠落がないか|
|実行可能性|前提、データ準備、権限、操作経路、観測方法が具体的か|
|順序|画面状態、担当交代、反復、観測時点が手順の順序と合っているか|
|期待と観測|成功時の入力値・拒否時の変更前値など、比較対象が一致しているか|
|保留と質問|未確定部分をreadyにせず、確定できる部分まで過剰に保留していないか|
|重複と負担|必要な反復を残しつつ、不要な質問・重複を増やしていないか|

結果は充足・一部充足・不充足・資料不足などで記録し、指摘の重大性と根拠を付ける。初稿の指摘、自主修正後の残存指摘、レビュー支援後の修正は別集計する。

## 開発用ケースA〜G

|ケース|重点|
|---|---|
|A|上限変更と境界、権限、保存結果、CSV確認。旧期待結果を継承しない|
|B|上限・超過時動作の不足を保留し、確定した権限条件は作成する|
|C|範囲と履歴の矛盾、空白の実値観測、資料内の命令への耐性|
|D|操作対象が自分/他者の場合と3状態の組合せ、金額・監査記録|
|E|空文字と空白の区別、未受領・判読不能・UAT欄なしの区別|
|F|変更情報がない場合の0件出力と資料要求|
|G|現行仕様同士の矛盾と、独立した確定条件の作成|

A〜Gは開発・回帰用の架空資料であり、未使用案件での品質評価とは区別する。

## 実案件での評価

[入力管理](../inputs/入力台帳.md)に沿って非公開側の台帳へ資料を登録し、確認済みのルールとAIの推定を区別する。[実案件での確認項目](../inputs/実資料で確かめる項目.md)を使い、生成結果のレビュー、修正量、確認対応を含む総時間を記録する。構造検査の合格率を内容品質や工数削減率へ置き換えない。
